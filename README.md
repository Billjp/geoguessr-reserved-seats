# GeoGuessr Reserved Seat Probe

**試合前に予備のゲスト席を確保し、途中参加者へその席を引き継ぐ、GeoGuessr Party用の非公式拡張機能です。**

主催者が予約席数を設定すると、Partyロビーで予備ゲストを自動作成して接続を維持します。途中参加者が来たら、主催者が選んだ席の引き継ぎデータを渡します。参加者は、そのゲストとして試合への復帰を試せます。

現在のバージョンは **0.3.2（実験版）** です。試合内のIDは、開始前に確保したゲストのままです。途中参加者の通常アカウントIDへの変更には対応していません。

このプロジェクトは独立したフォルダーで動作します。Daily Botの導入・起動は不要です。

## できること・現在の制限

| 機能 | 対応状況 |
| --- | --- |
| 予約席数を自由に設定 | 0〜100の整数を指定可能。実際に確保できる数はPartyの空き枠まで |
| 試合前のゲスト作成・Party接続 | 主催者のロビーで自動実行 |
| 補助プログラムの起動・Partyコード取得 | 初回設定後は自動実行 |
| 主催者側のゲスト用タブ | 不要 |
| 予備席の手動引き継ぎ | 対応 |
| Duel中の参加申請通知とOK／NOボタン | 未実装 |
| 未使用席のピン複製・自動回答 | 未実装 |
| 試合開始後の新しい席の追加 | 非対応。開始前の予約が必要 |

**予約しているだけのゲストは回答しません。** 未使用席が得点・HPなどへ与える影響は未検証です。予備席は試合開始前に選手候補へ含めてください。ベンチのゲストを途中から選手へ追加できることは確認していません。

## 必要なもの

- 主催者：Windows、Microsoft EdgeまたはGoogle Chrome、Node.js 20.3以上。
- 途中参加者：この拡張を読み込めるEdgeまたはChromeと、GeoGuessrに未ログインの専用ブラウザープロファイル。
- ゲスト参加を許可したGeoGuessr Party。

Node.jsを新しく導入する場合は、[公式ダウンロードページ](https://nodejs.org/ja/download)のLTS版を使用してください。途中参加者が引き継ぎデータを読み込むだけなら、Node.jsや補助プログラムの登録は不要です。

## 主催者の初回セットアップ

### 1. ファイルを用意する

このREADMEがあるフォルダーを、削除・移動しない場所へ置きます。

GitHubからソースを取得した場合は、そのフォルダーでPowerShellを開き、依存ライブラリを導入してください。

```powershell
npm ci --ignore-scripts
```

リポジトリの「Download ZIP」から取得した場合も、このコマンドが必要です。別途、依存ライブラリを同梱した `geoguessr-party-auto-v0.3.2.zip` を配布する場合は、このコマンドを省略できます。`reserved-seat-probe-v0.3.2.zip` は拡張のみの更新用で、初回導入には補助プログラムも必要です。

### 2. 補助プログラムを登録する

使うブラウザーに合わせて、次のファイルをダブルクリックします。

| ブラウザー | 実行するファイル |
| --- | --- |
| Microsoft Edge | `setup-auto.cmd` |
| Google Chrome | `setup-chrome.cmd` |

この処理は、ブラウザーから予備席管理プログラムを起動できるようにする初回登録です。管理者権限は不要です。拡張の読み込みは次の手順で行います。

両方のブラウザーで使う場合は、このフォルダーで次を実行します。

```powershell
.\setup-native-host.ps1 -Browser Both
```

### 3. 拡張を読み込む

1. Edgeでは `edge://extensions`、Chromeでは `chrome://extensions` を開きます。
2. 「デベロッパーモード」をオンにします。
3. Edgeの「展開して読み込み」、またはChromeの「パッケージ化されていない拡張機能を読み込む」を選びます。
4. このプロジェクトの **`extension` フォルダー** を選びます。プロジェクト全体やZIPファイルを選ばないでください。
5. 「GeoGuessr Reserved Seat Probe」が表示され、バージョンが **0.3.2** であることを確認します。

通常の展開読み込みでの拡張IDは `jhnaeneipohbdhnahgihcaopomjlncbb` です。別IDの旧版が残っている場合は旧版を無効化または削除し、今回読み込んだ拡張を使用してください。

セットアップ後はブラウザーが補助プログラムを自動起動します。毎回のコマンド実行、Partyコード入力、接続キーの貼り付けは不要です。`start-companion.cmd` は旧方式の検証用で、通常の利用では使いません。

フォルダーを移動した場合や、使うWindowsユーザーを変更した場合は、補助プログラムを登録し直してください。

## 主催者の使い方

1. 通常アカウントで、自分が主催者のPartyロビーを開きます。
2. 拡張を開き、「予約席数」に希望する人数を入力して **「予約席数を保存」** を押します。たとえば5席でも、別の席数でも指定できます。
3. 予備ゲストの作成・接続が終わるのを待ちます。設定した数は保存され、次の新しいロビーでも使われます。
4. ロビーの表示が **「予約席 5/5 · 開始できます」** のようになったことを確認します。拡張では「確保済み」、各席には「接続中 · 開始前の選手候補」と表示されます。
5. 公式画面の選手一覧でも予備ゲストがベンチになっていないことを確認し、通常の開始ボタンで試合を始めます。

主催者は、通常アカウントのロビータブだけ用意すれば使えます。ゲストごとのタブや追加プロファイルは不要です。

自動予約は主催者の通常プロファイルで使用してください。シークレット／InPrivateでの自動予約には対応していません。ロビーの自動検出は標準URL（`/party/lobby/...`）と日本語URL（`/ja/party/lobby/...`）に対応しています。

### 席数とモード

入力できる上限と、実際のモード定員は別です。空き枠を超える人数を設定すると確保を停止するため、予約席数を減らすか、参加人数・モードを変更してください。

| モード | 席数の目安 |
| --- | --- |
| 通常のTeam Duels | 合計20人。主催者1人だけなら予備席は最大19席。他の参加者がいればその分減る |
| 旧Duels | 合計2人。主催者1人なら予備席は最大1席 |

3人以上で使用する場合は、モード画面の **「Duels 2–20」** を選び、「選択」ボタンで決定してください。内部モードは `TeamDuels` です。拡張はモードを変更しません。

予約席の準備中に対応する開始ボタンを押した場合、そのクリックを保留し、同じロビーで準備が整った時に実行します。クリックしていなければ、拡張だけで試合を開始することはありません。ページ移動や確保失敗時は保留を取り消します。この補助処理は公式画面の構造に依存するため、開始前の選手一覧も確認してください。

## 途中参加者へ席を引き継ぐ

### 主催者が行うこと

1. 拡張を開き、渡したい予備席の **「引き継ぐ」** を押します。
2. その席の補助プログラム側の接続が閉じ、「途中参加者へ渡す」欄に引き継ぎデータが表示されます。
3. データをコピーし、参加する本人へ直接渡します。

現在は、このデータを主催者が渡すことで参加を許可します。参加申請の通知やOK／NOボタンはありません。引き継いだ席も確保済みの席として数えられ、自動で別のゲストを補充することはありません。

小窓を閉じた場合は、同じ席の **「データを再表示」** で元のデータを表示できます。読み込み期限は最大10分で、ゲストのログイン期限によって短くなる場合があります。画面に表示された期限内に使ってください。再表示しても期限は延長しません。

### 途中参加者が行うこと

1. EdgeまたはChromeに **専用の新しいブラウザープロファイル** を用意します。GeoGuessrの通常アカウントにもゲストにもログインしないでください。
2. そのプロファイルで拡張一覧を開き、デベロッパーモードから `extension` フォルダーを読み込みます。Node.jsや `setup-auto.cmd`／`setup-chrome.cmd` の実行は不要です。
3. 専用プロファイルで `https://www.geoguessr.com/` を開きます。予約席数は0のままで構いません。
4. 拡張の「受け取る側」に、受け取った引き継ぎデータを貼り付けます。
5. 「使い捨てゲストの引き継ぎで、元のゲームタブは閉じています」にチェックし、**「同じゲストとして再参加を試す」** を押します。自動予約席の場合、元の接続は主催者の「引き継ぐ」で閉じられています。
6. 同じゲストIDでの本人確認後、公式のParty／Duel画面へ移動します。公式画面で試合への復帰と、自分の回答が反映されることを確認してください。

通常アカウントや別のゲストがすでに存在するプロファイルへの読み込みは拒否します。同じプロファイルでタブを増やしても、ログイン状態は分離されません。

## 予約の停止・更新

- 自動予約を止めるには、予約席数を **0** にして保存します。
- 特定の席を止めるには、その席の **「停止・一覧から削除」** を押します。設定した予約席数も減らしたい場合は、数を変更して保存してください。
- 停止後もPartyの名簿にゲストが残る場合があります。停止・削除操作で、すでに相手へ渡したゲストの操作権を取り消すことはできません。
- 拡張を更新するときはファイルを更新し、拡張一覧で再読み込みした後、Partyページも再読み込みします。補助プログラムの場所やNode.jsの配置が変わった場合はセットアップも再実行します。

**試合中は、主催者のブラウザー終了・拡張の再読み込み・補助プログラムの停止を避けてください。** 未引き継ぎ席の接続と認証情報を失い、同じ席を復元する機能はありません。予約席数の設定は残ります。

## 困ったとき

| 症状・表示 | 確認すること |
| --- | --- |
| 「補助プログラムの登録が見つかりません」 | 使うブラウザー用のセットアップを実行したか、登録後にフォルダーを移動していないか |
| 「補助プログラムへの接続が拒否されました」 | 拡張IDが上記と一致するか、別IDの旧版を開いていないか |
| 「起動できませんでした」「最初の応答前に終了しました」 | Node.js 20.3以上と依存ライブラリがあるか。ファイルを移動した場合はセットアップを再実行 |
| 0.3.0で「初回セットアップが必要です」と表示される | 拡張と補助プログラムを0.3.2へ更新。この旧表示だけでは未登録と断定できない |
| セットアップで `ws` が見つからない | このREADMEがあるフォルダーで `npm ci --ignore-scripts` を実行 |
| PowerShellでJSONの読み込みエラーが出る | 0.3.2のセットアップを使用。Windows PowerShell 5.1のUTF-8読み込みに対応済み |
| PowerShellの実行ポリシーで拒否される | 表示されたエラーと端末の管理設定を確認。セットアップは実行ポリシーを変更・回避しない |
| 予備席が作られない | 主催者の試合開始前ロビーか、ゲスト参加が許可されているか、空き枠が足りるか |
| 予備席が「ベンチ」になっている | 試合前に人数とモードを確認。「Duels 2–20」は「選択」で決定する |
| 受取側で読み込みを拒否される | 通常アカウント・別ゲストが未ログインの専用プロファイルか、期限内のデータか |

「状態を更新」は状況を確認するボタンです。席の作成に失敗した後、同じParty・同じ人数で自動再試行はしません。**試合開始前に原因を解消してから、0を保存し、希望する人数を保存し直してください。** 試合開始後に不足席を作ることはできません。

## データと権限

引き継ぎデータには、元のゲストとして操作するためのログイン情報が含まれます。参加する本人へ直接渡し、公開チャット・GitHub・スクリーンショットには載せないでください。読み込み期限はインポートの期限であり、すでに渡した操作権の失効期限ではありません。

主催者側の予備ゲスト認証情報は、補助プログラムのメモリに保持します。引き継ぎデータは拡張の保存領域へ保存しません。受取時は、専用プロファイルへゲストのログインCookieを設定します。通常アカウントの認証情報を引き継ぎデータや補助プログラムへ渡す処理はありません。外部の中継サービスも使いません。

拡張は、GeoGuessrのページ確認、ゲストCookieの読み込み・設定、予約席数の保存、補助プログラムとの通信のために権限を使用します。初回セットアップは、現在のWindowsユーザーのNative Messaging登録と、`native-messaging/` 内の起動ファイル生成を行います。

登録先はEdgeが `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.geoguessr.reserved_seats`、Chromeが `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.geoguessr.reserved_seats` です。仕組みの詳細は、[Edgeの公式資料](https://learn.microsoft.com/ja-jp/microsoft-edge/extensions/developer-guide/native-messaging)と[Chromeの公式資料](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)を参照してください。

## 開発・検証

このREADMEがあるフォルダーで実行します。

```powershell
npm ci --ignore-scripts
npm test
```

テストはGeoGuessrに接続せず、予約人数・定員判定、主催者確認、開始クリックの保留、Native Messaging、引き継ぎデータの検証などを確認します。

同一PC・同一ネットワーク上の独立したクライアント間では、Team Duelsの予備ゲスト引き継ぎと回答登録を確認しています。また、実機での利用者からの動作報告があります。別PC・別ネットワーク間の引き継ぎは未検証です。

- [EXPERIMENT.md](EXPERIMENT.md)：2026年10月4日の初期検証の記録。現在の機能一覧はこのREADMEを参照してください。
- [FEASIBILITY.md](FEASIBILITY.md)：公開クライアントの調査と方式の検討。

### ファイル構成

```text
.
├─ README.md                 日本語の導入・利用ガイド
├─ extension/                ブラウザー拡張本体
├─ native-host.mjs           Native Messagingの入口
├─ companion.mjs             予備席の管理
├─ probe.mjs                 公式APIの検証クライアント
├─ ws-presence.mjs           ゲストの在席接続
├─ setup-auto.cmd            Edge用の初回登録
├─ setup-chrome.cmd          Chrome用の初回登録

├─ package.json
├─ package-lock.json
└─ tests/                    オフライン検証
```

`native-messaging/` はセットアップ時、`node_modules/` は依存ライブラリ導入時に生成されます。

## GitHubへ公開する場合

独立したリポジトリとして公開する場合は、**このREADMEがあるフォルダーの内容だけ**をリポジトリのルートへ置いてください。Daily Botのソースや設定を一緒にアップロードする必要はありません。

ソース公開では、`README.md`、`extension/`、`.mjs`の実行ファイル、セットアップファイル、`package.json`、`package-lock.json`、テスト・説明資料、`.gitignore` を含めます。ローカルで生成した `native-messaging/` と `node_modules/` は含めず、利用者が各自の環境で生成します。ZIP配布物はGitHub Releasesへ添付できます。

同梱の `.gitignore` は、PC固有の起動設定、依存ライブラリ、ZIP配布物、実機検証ログと証拠画像を除外します。GitHubの画面から直接ファイルをアップロードする場合も、これらを選ばないでください。初期検証の説明資料にはローカルの証拠ファイル名が記載されていますが、証拠ファイル本体はソース公開の対象外です。

公開前に、引き継ぎデータやCookie、個人のログイン情報、現在使用中のPartyコードをコミットに含めていないことを確認してください。検証レポートや画面画像を別途添付する場合も、公開してよい内容だけを使用してください。
